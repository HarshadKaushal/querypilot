# AI review: Phase 1 authentication

Date: 2026-10-09
Scope: Google OIDC, local dev login, rotating refresh tokens, users, account deletion, audit
Related work: `users`, `refresh_tokens`, and `audit_log`

This file is the AI-assisted review for the Phase 1 change set. It has no commit hash yet because the work was not committed.

## What was reviewed

- The refresh token is never written to the JSON body or to an audit row. A unit test checks that a reused raw token does not appear in the audit list.
- Reuse revokes the family, including the replacement token. Logout revokes only the presented token, so a second device keeps working.
- Dev login returns 404 when the flag is off, and the process refuses to start if the flag is on in production.
- Google callback state is checked against the sealed cookie before any user row is written. A failed token exchange does not create a user.
- Response logs redact `set-cookie`, so a refresh token in that header is not written as plaintext by the request logger.
- Account deletion keeps an audit row and drops the user id on it. The email is not copied into the audit metadata.

## Decisions

- The access token is an HS256 JWT signed in `TokenService`. A general JWT library pulled ESM into the test runner. Google ID tokens still use `jose`, loaded only when a real Google exchange runs.
- The OAuth verifier is encrypted into `ayd_oauth` instead of being stored in Redis. The API stays stateless, and the cookie expires in 10 minutes.
- Compose sets `NODE_ENV=development` so the local stack can set a non-Secure cookie and allow the dev login. A production process with `DEV_LOGIN_ENABLED=true` does not boot.
- Login rate limits and a CSRF token for cookie routes are left for the quota and hardening phases. `SameSite=Lax` is the current cookie control.

## Reflections

The Prisma repository is not covered by the unit tests. Those tests use an in-memory repository with the same claim-if-unused rule. A migration applied to a real Postgres still needs a smoke call of `POST /v1/auth/dev/login` after the API image is rebuilt.

The deletion skeleton cannot remove connections or history, because those tables are not created yet. The next phase that adds them has to delete or cascade them from this method.

## Follow-ups

- Rebuild the API image so the running stack picks up the routes and runs the auth migration.
- Do not put a Google client secret in Compose or in git. Put it in `.env` when you have one.
- On the first commit, add a review file whose name includes the commit subject, and leave this file as the pre-commit review.
