# AI review: model layer (Phase 7 step 1)

Date: 2026-10-14
Base commit: `b9a3182` (feat: cap each user's unfinished jobs and schedule users fairly)

## What changed

The first step of Phase 7: how the platform talks to language models (ADR 0012). Nothing calls it yet; the ask pipeline is step 2.

**Core (`packages/core/src/llm`):**

- **`LlmProvider`:** the interface a model sits behind, with its types (`LlmJsonRequest`, `LlmResponse`, `LlmAttempt`) and `LlmError`, whose kinds are rate_limited, unavailable, bad_output, misconfigured, and cancelled.
- **`GeminiProvider`:** uses Google's official SDK (`@google/genai` 2.29) and the Interactions API.
  - Sends a system instruction, the prompt, and a JSON `response_format` with a schema; temperature 0, low thinking, `store: false`, SDK retries off.
  - Classifies failures by HTTP status.
  - Replaces provider error text with fixed sentences.
  - With no key, it fails as misconfigured without touching the network.
- **`LlmClient`:** the fallback chain.
  - Each answer shape is a Zod schema; `z.toJSONSchema` makes the JSON Schema for the model, and the same schema validates the answer.
  - Falls back on rate limits, outages, and malformed answers. Stops on a missing or refused key, and on cancellation.
  - Records every attempt (model, outcome, latency, tokens) for accounting.
- **`LlmModule`:** builds the primary (`gemini-3.8-flash`) and fallback (`gemini-3.5-flash-lite`) providers from settings.

**Settings:** `GEMINI_API_KEY` (optional), `LLM_PRIMARY_MODEL`, `LLM_FALLBACK_MODEL`, `LLM_TIMEOUT_MS`. Compose passes the key to the worker from the root `.env`. Log redaction adds `*.apiKey`.

**Tests and tools:**

- `FakeLlmProvider` in `@ayd/core/testing` answers from a script and records requests.
- `npm run try-llm --workspace=@ayd/worker` checks a real key with one small structured request.

**Docs:** ADR 0012, features, implementation (Phase 7 section), testing (fake provider), and `.env.example`.

## Suggestions accepted

- **Free models:** `gemini-3.8-flash` as primary and `gemini-3.5-flash-lite` as fallback (the user asked for free models; these are the two Google recommends for new projects).
- **Keep the raw-SQL job route**, guarded (user's choice).
- **Rows go to the model only when the connection allows it** (user's choice, applied in step 4).
- **Step-by-step commits** for Phase 7 (user's choice).
- **Zod as the single definition of each answer**, so the model's output and the code cannot disagree on its shape.

## Suggestions rejected

- **Calling the REST API with `fetch` by hand.** The Interactions API is new and its documentation thin; the official SDK carries the exact types.
- **Preview models** (stricter limits, shorter life) and the **2.5 family** (Google now limits it to existing users).
- **Making `GEMINI_API_KEY` required.** The worker would not start on a laptop without a key, and every non-model job would stop working too.

## Decisions

- **A 400 or 404 counts as bad output and falls back.** An unknown model name or an unsupported schema is specific to that model. A 401 or 403 stops, since the fallback uses the same key.
- **No live call was made.** No key was available yet, and tests must not call models. The SDK was loaded from the built provider to confirm `interactions.create` exists, and the unit tests pin the exact request sent.
