# AI review: Phase 3 tables for schema snapshots and the allowlist

Date: 2026-10-12
Base commit: `b3ccee8` (fix: harden the read-only probe and repair local dev setup)

## What changed

First slice of Phase 3. ADR 0008 records how snapshots and the allowlist work. The Prisma schema gains `SchemaSnapshot` (`schema_snapshots`) and `AllowedObject` (`allowed_objects`), and migration `20261012120000_schema_allowlist` creates them. Both reference `connections` with `ON DELETE CASCADE`, so deleting a connection or an account removes them. No code reads or writes them yet.

## AI usage

An AI assistant (Claude Code) proposed the Phase 3 design and the three product choices. The developer picked the assistant's recommendations: allow every table and non-sensitive column on the first snapshot, keep objects found by a later refresh hidden until allowed, and ignore PostgreSQL comments. The assistant wrote the ADR, the models, and the test. The migration SQL was generated by `prisma migrate diff` from the previous schema, not written by hand.

## Suggestions accepted

- Store the whole introspected structure as one JSON document per version, because the allowlist editor needs every table, not only the allowed ones.
- An allowlist of explicit rows: a table row, plus one row per allowed column. A new column on an allowed table then stays hidden until someone allows it.
- Key the future SQL cache on a fingerprint of the allowed schema, so allowlist edits invalidate it too, not only refreshes.
- Prove the cascade with an integration test instead of trusting the schema file.

## Suggestions rejected

- A unique index on (connection, schema, table, column). PostgreSQL treats NULL column names as distinct, so it would not stop duplicate table rows. The allowlist is replaced as a whole inside a transaction, and the code rejects duplicates.
- An `allowlist_revision` column on `connections`. The fingerprint covers the same need with no extra state.
- Importing PostgreSQL comments as descriptions. The developer chose to keep only descriptions they write.

## Decisions

- No snapshot stores row data or comments. The document holds names, types, nullability, primary keys, and foreign keys.
- `prisma format` re-aligned the existing `Connection` model. Only whitespace changed in those lines.

## What was checked

- The migration applied to the local application database.
- Integration tests: 15 pass. The new file checks that a second snapshot with the same version fails with `P2002`, and that deleting the user removes the snapshot and both allowlist rows.
- The API type-checks against the regenerated Prisma client.
